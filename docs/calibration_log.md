# 較正ファイルを作るチュートリアル(tutorials_caldata/4_MakeCalibration)の作業記録

## 2026-10-13 作り始め

小野田の依頼: `tutorials_caldata` に較正を作るフォルダを作り、ノートブックでドリフト速度の算出、
`Cathode_1Hit_board_A7_C7` のような 1 ヒットのスペクトル(領域を ASIC ごと/ボードごとで選べる、閾値も選べる)、
そのスペクトルを使ったゲインマップの作成をする。

### 入力: 全イベントの生データツリー

- `run_chain.py` に `--set モジュール.パラメータ=値`(設定ファイルの値の上書き)を追加。値は JSON として読む
  (`10` は整数になり、double のパラメータには入らない → `10.0` と書く)。
- `run_chain.py smile2p_20190701_Per02 -o cache/Per02_raw_cal_thr10.root --raw --compression 505
  --set RawTreeWriter.save_threshold=10.0 --set RawTreeWriter.save_ha=false`
  - `save_threshold=10`: 波形の最大値がベースライン + 10 ADU 以下のチャンネルは保存しない。電荷の閾値が 10 以上なら、
    保存しなかったチャンネルはどのみち「閾値を超えるサンプルなし」なので、結果は全部保存した場合と同じ。
  - 約 80 分(シミュレーションの 8 プロセスと並行)、約 5 GB。

### ドリフト速度(`DriftVelocity.ipynb`)

- 研究室のマクロ `drift_speed_s2p_v3.C`(小野田が提供)と同じ手順。入力は SMILE_tool_box の RawRead2p のヒストグラム
  `HitMap_AD/CD`(ストリップ × クロック、ヒットしたストリップ 1 本ごと)と `Drift_V_Anode/Cathode`
  (時間 [時] × クロック、ボードごとにヒットのあるクロック 1 つごと。`NumTimeBin 1800`、`HistTimeWidth 300` → 10 分)。
  生データツリーのヒットから同じものを作る(`Drift_V` の時間は `anode_time[0]`。SMILE_tool_box はボードごとの時刻)。
- offset: クロック分布の微分 |h[b+1] − h[b]| の 0〜200 で最大のビン。アノードは 82 に固定、カソードは最大のビン、平均。
  ドリフト面側の端: 512〜1024 の微分をガウス関数でフィット(初期値は `SetFitParameter` のモーメント、範囲は平均 ± 1.5 RMS)、
  10 分ごと(`GetTGraphStartEnd` のやり直しの規則も同じ)。v = 305 mm / (端 − offset)、pol1 / pol2 の χ² の和の小さい方、
  アノードとカソードの平均を書く。時間のビンが 1 つのときはマクロの特別な場合と同じ。
- 先頭 5000 イベントでの確認: 微分の最大はアノード 82、カソード 88 → offset 85(データに付いている
  `Per02_ETCC/drift_velocity.dat` の 85 と一致)。端は 5000 イベントでは統計が足りずフィットが広がる(全イベントで確認する)。

### 1 ヒットのスペクトルとゲインマップ(`GainMap.ipynb`)

- ゲインマップ(`Calibration20190130.dat`): 144 行 = アノード 12 ch × カソード 12 ch、E = a Q + b(Q はアノードの電荷 [pC])。
  TPC_Calibration は a, b に `Cal_Modify` を掛けて使う。
- 1 ヒットの選び方は EricaNext 開発版(`~/ANLNext/Erica_git_dev`)の CalcFADC と同じ:
  ASIC ごと = 電荷が正のチャンネルがアノード 1 本・カソード 1 本だけ、ボードごと = 電荷が正のチャンネルを持つボードが各 1 枚だけ
  (電荷は正のチャンネルの和)。
- 電荷は本流の CalcFADC と同じ定義(pC、サンプル 30〜499、閾値を超えないチャンネルは −80)。開発版は ADU × クロック(0.8 を掛けない)、
  サンプル 511 まで、閾値を超えないチャンネルは 0。→ 横軸が約 0.8 倍違う。
  C++ の `charges` と、チェーンと一致を確認済みの Python の関数の差は最大 3e-11 pC(足し算の順番)。
- Per02 では反応したボードの 4 チャンネルがほとんど同時に正になる(先頭 5000 イベント、閾値 20: 反応したアノードのボード 7205 個のうち
  4 ch とも正 5368、1 ch だけ 123)。→ 閾値 20 では ASIC ごとの 1 ヒットはほとんど無い(カソードで 1 ch だけのイベントは 0)。ボードごとは 2360 イベント。
- 既知のピーク(エネルギーと電荷の範囲)は `PEAKS` に書く形にした。
- **ゲインマップは Ba の線源のデータで作る必要がある(小野田、2026-10-13)。** Per02(Cs-137)では作れないので、ゲインマップの部分は「準備中」。
  ノートブックは 1 ヒットのスペクトルまでを Per02 で扱い、7 節は Ba のデータ用の骨組みとして残す。
  空のときは元の表をそのまま書き出す(144 行、同じ並びになることを確認)。

### ドリフト速度: 全イベントでの確認と Drift_V の作り方の修正(2026-10-13)

- 1 回目(ヒットしたストリップから「ボード × クロック」を作った版)を全イベントで実行: offset 85 は一致。速度はデータに付いている
  `Per02_ETCC/drift_velocity.dat` と最大 5.6e-4 mm/clock(0.15 %)の差。
- リファレンスの出力 `sm2+_cal_rootdata/20190701_Per02/haboc_tmp_0.root` の `RawRead2p` に `HitMap_AD/CD`、`Drift_V_Anode/Cathode` が残っていた。
  - `HitMap`: こちらの方が 27,817 ヒット多い(参照が読み飛ばした 27 イベントの分。per02_comparison_log の 30)。全時間でのフィットは同じ(端 835.22)。
  - `Drift_V`: 最初の 10 分のビンで 1.8 % 少なかった。RawRead2p はエンコーダーの記録(ボード・クロックごと)を、**ストリップのビットが全部 0 でも**
    数えている。また時刻はボードごと(カソードは `cathode_time`)。
  - リファレンスのヒストグラムにノートブックの手順を当てると、ファイルとの差は 1.1e-4(0.03 %)。
- 対処: ReadData に記録の一覧(`Get_RecordBoardA/C`, `Get_RecordClockA/C`)とカソードの時刻(`Get_CathodeTime`)を追加、
  RawTreeWriter に枝 `rec_a_board`, `rec_a_clock`, `rec_c_board`, `rec_c_clock`, `cathode_time` を追加。
  先頭 25000 イベントで作った `Drift_V` の最初の 10 分のビンが、アノード・カソードともクロックごとにリファレンスと完全に一致。
  → ノートブックの `Drift_V` をこの枝から作るように変更。較正用の生データツリーを作り直し中。
- マクロの式の選び方(χ² の和の小さい方)では、同じ点に当てるので 2 次式がほぼ必ず選ばれる(Per02 では最後の途中までのビンに引っぱられる)。
  データに付いているファイルは完全な直線(10 分ごとに −3.3e-5)。マクロにはロバストフィット(`ROB=0.8`)の行がコメントアウトで残っているので、
  当時は別の設定だった可能性。ノートブックに `FIT_DEGREE`("auto" / 1 / 2)を追加。
- 作り直した生データツリー(記録の枝入り)で全イベントを実行(2026-10-13): offset 85(一致)、速度の差は最大 1.07e-4 mm/clock(**0.028 %**)。
  リファレンスのヒストグラムに当てた場合(1.06e-4)と同じ → `Drift_V` の作り方の差は解消。
  `FIT_DEGREE = 1` でも差は 1.06e-4。残りの差は当時のフィットの設定(ロバストフィットなど)や ROOT のバージョンの差と思われる。
  z に直して 0.1 mm 以下なので実用上は問題ない。ノートブックは実行結果付きで保存(`FIT_DEGREE = "auto"`)。
- 2026-10-14 小野田: ノートブックではデータに付いているファイルと比べず、合っているものとして説明する(裏での一致の確認は必要)。
  → ノートブックから比較のセルと図を消し、確認は `run_script/check_drift_velocity.py` に分けた(offset が違うか、
  速度の相対差が 1e-3 を超えると終了コード 1)。実行し直したノートブックの出力で OK(offset 85 = 85、相対差の最大 2.8e-4)。

### ゲインマップの作り方: Calamity_v5.0(2026-10-14、小野田の指定、`hikaru3_analysis2/TPC_caldata/Calamity_v5.0`、読むだけ)

- 入力: 線源ごとの ROOT ファイル(Ba-133、Cd-109)の `TCAL/SPEC_1Hit_A{アノード}_C{カソード}`(ASIC の組ごとの 1 ヒットのスペクトル、[pC])。
  起動例: `[Prog] 0 5 6 11 Per_01_Ba133.root Per_03_Cd109_SE.root`(アノード・カソードの範囲、2 つのファイル)。
- ピーク: Ba-133 30.85 keV と 8.04 keV、Cd-109 22.10 keV。
- ① ピーク探し(`Peak_Search1`): rebin(既定 40)、250〜5000 pC の外を 0 にし、`TSpectrum::Search(h, sigma, "nodraw", 1 - 0.5^thre_n)` で
  見つかったピーク数が欲しい数になるまで thre_n(多すぎたら ×2、少なすぎたら ÷3、100 回)と sigma(同じく ×2 / ÷3、10 回)を変える。
- ② 対応づけ: ピークを電荷の大きい順に並べ(`Sort_X`)、エネルギーの大きい順(30.85 → 8.04)と組にする。
- ③ 較正(`Calibration`): **原点 (0, 0) を加えた** 4 点(0, 8.04, 22.10, 30.85 keV)に `pol1` を TGraph で当てる(重みなし)→ 傾き Ka、切片 Kb。
  χ² のマップを見て、おかしい組は GUI でピークの印を動かしてやり直す(「目分量」)。
- ④ 保存(`Cal_Save`): ` アノード\tカソード\tKa\tKb` を追記(TPC_Calibration が読む形)。
- `macro/Gain.c`: ガス増幅率のマップ = (W/e) / Ka / 700(W = 23.6 eV、e = 1.6e-7 pC)。`Fit_Energy`: Ka, Kb で焼き直してガウスフィット → 分解能。
- データ: `TPC_caldata/20171219/Per01,08,09,10,12_TPC`、`20171220/Per01,02,03_TPC`。出力の例 `TPC_caldata/Calibration20171219.dat`(144 行)。
  どの run が Ba-133 / Cd-109 かは未確認(小野田の準備待ち)。

- `GainMap.ipynb` を Calamity_v5.0 の手順で作り直した(Ba-133 の 30.85 keV と 8.04 keV、原点を加えた 3 点に pol1、TSpectrum のピーク探しは Peak_Search1 と同じ、

  よく当たった中央の組は、当時の `TPC_caldata/Calibration20171219.dat` と Ka が 2〜4 % で一致(A5C5 0.0190 / 0.0193、A6C6 0.0237 / 0.0230)。
  残りの差はピークの位置が 80 pC のビンの中心になる粗さ。20171220 の run を足して作り直す。

  ファイルは壊れていない(各ファイルはイベントの区切りで終わる)。00005〜00006 だけ、または 00000〜00007 だけのリンクのフォルダでは
  波形ありでも最後まで読める。→ 6 run を同時にマウント先から読んでいて、次のファイルを開く(`ifstream::open`)が一時的に失敗し、
  TPC_Encoder がそれをデータの終わりと見なして run 全体を止めていたと判断。

  同時に読む run を 3 つまでにして流し直し中。

## 2026-10-15 ゲインマップ(全 12 run)

- 20171219 の 5 run と 20171220 の 7 run(Per06 は 6,230,941 イベント)の生データツリーがそろい、`GainMap.ipynb` を全 run で実行(1 ヒット 2,458,492 イベント)。
- 自動のピーク探し(Calamity の Peak_Search1)で 144 組すべてに 2 本見つかったが、7 組が χ² > 5(A1C0, A1C1, A1C10, A2C1, A7C0, A7C2, A8C0)。
  どれも 1 ヒットが 4000〜12000 と少ない組で、30.85 keV のピーク(1500〜2000 pC)ではなく別の山を拾っていた。範囲を決めたガウス関数のフィットも位置が安定しない。
- 小野田の判断で、Calamity の「目分量」と同じく図(20 pC のビン)を見て `MANUAL_PEAKS` に書いた(精度 ±50〜100 pC):
  A1C1 [1950, 580]、A1C10 [1750, 540]、A2C1 [1930, 540]、A7C0 [1700, 430]、A7C2 [1550, 400]、A8C0 [1800, 430] pC(30.85 keV, 8.04 keV)。
  A1C0 は 30.85 keV のピークが見えないので較正しない(0)。
- 結果: 143 / 144 組を較正、χ² > 5 は 0 組。出力 `tutorials_caldata/cache/Calibration_Ba133_2017_thr20.dat`。
- 裏での確認(ノートブックには書かない): 当時の `TPC_caldata/Calibration20171219.dat`(20171219 の run だけで作ったもの)と Ka を比べると、
  143 組の比の中央値 0.998、16〜84 % 点 0.92〜1.07。手で直した 6 組の比は 0.86〜1.07(A8C0 が 0.86)。

## 2026-10-15 ゲインマップをガウス関数のフィットで作る

- Calamity の方法(`TSpectrum` が見つけたビンの位置をそのままピークの位置にする)で作ったゲインマップに、Calamity の `Fit`
  (較正したスペクトルの 30.85 keV のピークにガウス関数)を当てると、143 組中 39 組で 30.85 keV のピークに当たらなかった。
  3 点の直線の χ² ではピーク探しの取り違えが分からない。
- 小野田の判断: ゲインマップはピークにガウス関数(1 つ)を当てて作る。Calamity の方法は参照用(`4_MakeCalibration/reference/GainMap_Calamity.ipynb`、
  出力 `Calibration_Ba133_2017_thr20_calamity.dat`)。
- `GainMap.ipynb`: `TSpectrum`(+ `MANUAL_PEAKS`)の位置を初期値に、各ピークに gaus + expo を当てる(20 pC のビン)。
  - 範囲: 30.85 keV は初期値の 0.55〜1.6 倍、8.04 keV は 0.75〜1.3 倍。σ の制限 30.85 keV 5〜50 %、8.04 keV 4〜30 %、背景の傾きは範囲の中で e^5 倍まで。
  - 2 段階(μ, σ を固定して高さと背景 → 制限付きで全部)。制限を外して当て直すと、統計の少ない組で背景の指数関数が範囲の端で暴走した(図で何桁も跳ねる)のでやめた。
  - ピークの有無は A / A の誤差ではなく S/√N(μ ± 2σ の「データ − 背景」の和 / √データの和)> 3 で判定(A の誤差は背景と相関して大きく出る)。
    8.04 keV の背景を 1 次式にすると悪くなった(144 組中 104 組が外れる)ので、両方とも指数関数。
  - 判定: 状態 0 か 1(Minuit2)、χ²/ndf < 3、S/√N > 3、μ と σ が制限の端でない、μ の誤差 < 10 %、μ30.85/μ8.04 が 3.2〜4.6。
- 結果: 94 / 144 組を較正(Ka の中央値 0.0192 keV/pC、Kb の中央値 −0.05 keV)。較正しない 50 組は、アノード 0 の列の 12 組全部と、端の ch に多い。
- 裏での確認: 当時の `TPC_caldata/Calibration20171219.dat` との Ka の比は 94 組で中央値 0.984、16〜84 % 点 0.94〜1.02
  (Calamity の方法では 0.92〜1.07)。同じデータの Calamity の方法との比は中央値 0.985、0.96〜1.01。
- 較正しない 50 組の扱い(小野田の判断): Ka = Kb = 0 のまま(参照のゲインマップの値や周りの組の平均では埋めない)。
  当時の `Calibration20171219.dat` は 144 組すべて値あり(Ka 0.0152〜0.0249、Kb −0.06〜0.02、アノード 0 の列も 0.016〜0.020)。
  50 組の参照の Ka は 0.0152〜0.0219 で普通の値。参照がどう決めたかはファイルからは分からない(Kb がほぼ 0 なので、Calamity で目分量で直したと思われる)。
